Actions

Button

Buttons start an action. **One `primary` per view** for the main thing the page is for; `secondary` (outlined) for other actions; `ghost` in toolbars, tables and cards; `soft` for low-emphasis fills; `destructive` only inside a confirmation dialog; `highlight` (lime) for rare celebratory actions; `link` inline in text.

Actions

IconButton

A square button with only an icon, for toolbars, table rows and dialogs. **Always pass `label`**: it becomes the `aria-label` and tooltip. Variants: `ghost` (default) and `outline`; sizes `md` (36) and `sm` (28).

Forms

Input

Single-line text with a label above. Props: `label`, `hint`, `error`, `required`, `optional`, `prefix` and `suffix` (₹, %, .com), `icon`, `size="xl"` for phones, plus every native input prop.

Forms

Textarea

Multi-line text for notes, scope and messages. Same label, hint and error rules as `Input`. Starts at 3 rows and resizes vertically.

Forms

Select

A native select styled to match `Input`. Use it for short fixed lists (currency, GST type, lead source). For long or searchable lists the app uses a combobox (shadcn Command in a Popover).

Forms

Checkbox

Binary choices and multi-select in lists and tables. The box border is `input` (3:1); checked fills `primary`. Put the label to the right; add a `description` for consequences.

Forms

Switch

Settings that take effect immediately (no Save button). Use a checkbox when a form has a Save button. The off track is `input`, on is `primary`.

Status

Badge

One or two words of status. Tones: `neutral`, `brand`, `success`, `warning`, `danger`, `info`, `highlight`, `outline`. Add `dot` for live status (Overdue, Waiting) so meaning never rests on colour alone. Use `size="sm"` inside cards and tables.

Status

Avatar

People and companies. Shows a photo when `src` is given, otherwise initials on a tint picked from the name (stable per person). Sizes `xs` 20, `sm` 24, `md` 32, `lg` 48 (rounded square, for company records). `AvatarGroup` stacks people with a +N overflow.

Status

Progress

A thin bar for progress toward a known end: onboarding, budget used, a phase. Tones: default (`primary`), `success`, `danger` (over budget), `highlight`. Give it a `label` and `showValue` when the number matters.

Status

Skeleton

Placeholder shapes while data loads, matching the real layout so nothing jumps. Shimmer stops under reduced motion. Prefer skeletons to spinners for anything that takes longer than about 300 ms.

Navigation

Tabs

Switch between views of one record (Overview, Phases, Tasks, Files, Invoices). Underlined, with optional counts. Use `Segmented` to switch the *display* of the same data (Board / List / Calendar).

Navigation

Segmented

A compact switch between two to four display modes of the same data. Not for navigation between pages.

Navigation

Sidebar

The app's main navigation, grouped by how each role works.

Navigation

CommandPalette

Ctrl/Cmd+K from anywhere: jump to any lead, client, project or invoice, or run an action (New lead, Create invoice, Switch workspace). Results are grouped; the highlighted row shows where Enter goes. Every action in the app should be reachable here.

Containers

Card

The basic surface: `card` with a 1px `border` and `radius-lg`, no shadow. Give it a `title` (`title-sm`), optional `description`, `icon` and `actions`. Use `flush` when the body is a table or list that runs edge to edge. Don't nest cards inside cards.

Feedback

Alert

An inline message in the page about this screen's state. Tones: `info`, `success`, `warning`, `danger`, `brand`. Lead with what happened, then what to do; add one `action`. For confirmations of an action just taken, use a `Toast`.

Feedback

Toast

A short confirmation of what just happened, bottom right on desktop and top on phones, for 5 seconds. Past tense ("Proposal sent"). Include **Undo** for reversible actions instead of asking for confirmation first.

Feedback

Dialog

Focused decisions that block the page: confirming a destructive action, or a short form. Title states the decision; the description states the consequence; the destructive button names the action ("Delete lead"), never "OK". Escape and the X close it; focus is trapped and returns to the trigger.

Feedback

EmptyState

What a screen shows before it has data: a duotone icon, a title that says what will be here, one sentence on why it matters, and one primary action (plus an optional secondary). Empty states are onboarding. Use `compact` inside cards.

Data

MetricCard

A number people decide on, linking to the list behind it. Label (with icon), value in `metric` with tabular figures, a delta badge, a note, and an optional sparkline. Set `inverse` when down is good (overdue). `tone="danger"` colours the value for money at risk.

ActivityFeed

A timeline of what happened on a record (lead, project, client): who, what, when. Icons in tinted circles mark the kind of event. Newest first; relative time for the last 7 days, then dates.

Agency OS patterns

Checklist

The onboarding checklist that gets a new workspace to its first proposal in minutes. Done steps are ticked with lime; the next step is highlighted and carries its action; progress shows at the top. It can be dismissed and reopened from Help.

Agency OS patterns

RecordHeader

The top of every record page (lead, client, project, invoice): avatar or icon, `title-lg` name, status badge, a meta row (owner, value, dates, location) and the record's actions (secondary first, one primary). Tabs sit directly below.

Brand

Icon

Phosphor icons. Pass `name` (kebab-case), `size` (16 inline, 18 to 20 navigation, 28 to 36 empty states), `weight` (`regular` default, `fill` for the selected nav item, `duotone` for empty states) and `label` when the icon carries meaning on its own. The grid shows the icons built into this system.

Brand

Logo

The Agency OS lockup: the glyph in `primary` and the wordmark in Geist SemiBold. On a violet or ink tile the glyph is lime (`highlight`), as in the sidebar workspace tile. Keep clear space equal to the glyph's height. No dedicated Agency OS logo has been drawn yet.
