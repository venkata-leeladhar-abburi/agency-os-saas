# @agency-os/db

Drizzle schema, migrations, row-level security and the data functions the app calls.

## What's here

| Path                      | What                                                                                                                                                                                                                                                        |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/schema/`             | Drizzle tables. M5: `profiles`, `workspaces`, `memberships`, `role_permissions`, `invitations`, `audit_log`.                                                                                                                                                |
| `migrations/0000_*.sql`   | Generated by `pnpm generate` from the schema.                                                                                                                                                                                                               |
| `migrations/0001_rls.sql` | Hand-written: RLS on every table, the policy functions (`is_member`, `has_permission`, `permission_scope`), `create_workspace`, `accept_invitation`, the last-owner guard and the role permission seed (generated from `packages/core/src/permissions.ts`). |
| `src/client.ts`           | `connect()`, `withUser(db, session, fn)` and `withService(db, workspaceId, fn)`. The only ways to reach the database.                                                                                                                                       |
| `src/accounts.ts`         | Workspaces, members, roles and invitations.                                                                                                                                                                                                                 |
| `test/`                   | Database tests against a real Postgres, including cross-tenant checks.                                                                                                                                                                                      |

## Rules

- Every tenant table has `workspace_id`, `enable` and `force row level security`, and a policy built on `is_member()` and `has_permission()`.
- App code uses `withUser()`, which runs the transaction as the `authenticated` role with the user's JWT claims, so RLS decides what it can see. Jobs and webhooks use `withService(workspaceId)` and must filter by that workspace themselves.
- Migrations are forward-only. A permission change goes in `packages/core/src/permissions.ts` and a new migration that updates `role_permissions`; a test checks the two match.

## Commands

```sh
pnpm --filter @agency-os/db test       # needs Postgres; TEST_DATABASE_URL defaults to postgresql://postgres:postgres@localhost:5432/postgres
pnpm --filter @agency-os/db generate   # new migration from schema changes
DATABASE_URL_DIRECT=… pnpm --filter @agency-os/db migrate
```

Tests create a throwaway database, apply `test/supabase-shim.sql` (the `auth` schema and roles Supabase provides; local and CI only) and every migration, then drop it.
